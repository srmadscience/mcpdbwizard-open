# --- test-schema DDL ---------------------------------------------------------
# NOT NEGOTIABLE, and the reason is not tidiness: sql/ and OtherDbs/ are not only our own
# throwaway fixtures. Several of the schemas in them are the table and package layout of
# THIRD-PARTY systems, carried over from customer work years ago. Structure only -- the data
# dumps were already gone -- but another organisation's schema is not ours to publish, so
# both trees stay behind regardless of how useful a fixture would be to a contributor.
#
# THIS FILE SHIPS, so it does not name them; the private CLAUDE.md does. That is not
# secrecy theatre -- an exclusion list that enumerates what it is protecting publishes the
# index it exists to withhold.
#
# The build does not need any of it. No test under src/test/java reads sql/ or
# OtherDbs/; the live-database tests reach a SERVER, and skip when there is not one.
# Verified by exporting and running `mvn test` in the staged tree -- see
# export-open-source.sh, which now does exactly that as its last step.
#
# What a contributor loses: the fixtures behind the live tests and the generated-code
# harnesses. Those tests SKIP without a database anyway, so a clone is still green.

# --- the generator configs, and the statement library -------------------------
# A config ENUMERATES the schema it introspects. generic_test1 alone names 323 procedures and 211
# tables, and since statements are stored inline their text carries column lists too. So the
# schema's shape shipped inside the configs while its CREATE statements stayed behind -- which
# defeats the point of withholding the DDL.
#
# WHY ALL OF THEM, and not just the ones connecting as the private user: that was tried and it
# LEAKED. Keying on the USER a config connects as is too narrow -- the field says who it logs in
# as, not whose objects it names. Six configs connecting as another schema still carried a dozen
# of the private schema's object names each, through synonyms and cross-schema references, and
# only one of the 41 came out genuinely clean.
#
# Per-NAME filtering does not work either: the fixtures were cloned between schemas years ago, so
# the same object names occur in several of them and a name-based check cannot say whose they are.
# It over-reports, and a check that cannot be trusted gets ignored.
#
# NOTE TO WHOEVER EDITS THIS FILE: it SHIPS. Do not illustrate any rule here with a real object
# name -- that happened four times in one day while writing these very entries, and each time the
# explanation of an exclusion published a sample of the thing being excluded. Keep examples in
# the private CLAUDE.md.
#
# Stripping the names in place is not an option: a config with no object names generates nothing,
# so "remove the names" and "do not ship the config" are the same act.
#
# What is lost: the worked examples of the config format. The format itself is still documented,
# and com.mcpdbwizard.schema (Schema, ConfigConverter) round-trips it both ways in code that does
# ship. What is NOT lost: the generator, the runtime library, and a database-free suite that
# passes on a fresh clone.
Propfiles/
