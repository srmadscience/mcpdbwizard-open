# Minimum number of .java files each propfile must generate.
#
# WHY: generation can lose its database connection part-way -- ORA-17008 mid-run --
# and still exit 0 with "Finished processing file" in the log. The result is a tree
# with a handful of files instead of hundreds, and NOTHING else notices:
#
#   2026-08-02, ORCL19: generic_testf produced 1 file instead of 206. The suite
#   still reported 336/0/2, because no harness imports generic_testf. It was found
#   only by comparing total file counts against another box by hand.
#
# The provisioning check verifies that fixtures exist BEFORE generation. This file
# covers the other end: that generation actually produced them.
#
# THESE ARE FLOORS, NOT EXACT COUNTS, because the same propfile legitimately yields
# different totals per Oracle version. 12c returns the full ALL_ARGUMENTS walk while
# 18c/19c/21c/23ai truncate it and go through the ALL_PLSQL_* synthesis arms, so 12c
# produces MORE:
#
#   generic_test1  2486 on ORCL12  vs  2456 elsewhere   (measured six-box, 2026-08-20)
#
# 2026-08-11, per-propfile SQL directories (docs/missing-sql-file-plan.md): four floors rose
# because four configs finally get a statement class they had always asked for and silently
# not received -- generic_test1(+1, bfilenameFactory) and generic_testf(+5, the flight
# statements), each with its _mcp sibling. Set from XE18, a TRUNCATING box, because these are
# cross-version MINIMUMS: ORCL12 measures 2488/2489/211/212 and using its numbers would put
# the floor above what every other box can reach. The 31 other propfiles did not move at all,
# which is the check that the change reached only the configs that named the missing files.
#   generic_test4   131 on ORCL12  vs   129 elsewhere
#   generic_testb   101 on ORCL12  vs    99 elsewhere
#   generic_testd   121 on ORCL12  vs   119 elsewhere
#
# Each floor below is the LOWEST count observed across the boxes, so a version
# difference passes and a collapse fails. Update a number here deliberately when a
# change legitimately alters output -- that edit is the record of the decision.
#
# KNOWN LIMITATION: generic_test_23ai generates 182 files on a 23ai-line server but
# only 61 on an older one, where its fixtures cannot exist (the "hollow" tree). The
# floor must therefore be 60, so a collapse from 182 to 61 on a 23ai box would slip
# through this check. (Those two figures read 181/60 until 2026-08-11 and were prose
# rather than assertions, so nothing caught the drift; measured 182 on BOTH FREE23 and
# FREE26 and 61 on ORCL12 that day, with this propfile's generator input byte-identical
# to before -- it has no per-propfile SQL overlay, so the per-propfile-directory work
# cannot have moved it. The floor of 60 below is what is actually enforced.) That case is already covered elsewhere -- the no-gen23ai Maven
# profile keys off a deep marker file, and TGen23ai/TGen23aiMcp fail outright against
# a hollow tree.
#
# Format: <propfile> <minimum files>   ('#' comments and blank lines ignored)
