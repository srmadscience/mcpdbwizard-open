## Why

**CHARGLT is the sharper case, and it is the reason this is one plan rather than two.** It is the
named regression config for two defects fixed on 2026-09-03, and the only thing standing behind
those fixes today is a **file count of 97** in `expected-file-counts.txt` — that is, generation
succeeded. Consider what a count cannot see:

- The `processMany` defect: the TIMESTAMP arm emitted **no assignment at all**, so every *multi-row*
  read returned that column as null. The file was emitted. It compiled. `get_by_pk` and the index
  lookup disagreed about the same row. The count is identical either side of the fix.
- The index-lookup defect: the generated server **did not compile**. That one a regen does catch —
  which is precisely why the other one is the half worth worrying about.

`charglt.pb2` holds five index lookups over TIMESTAMP columns and is the only propfile with a
TIMESTAMP inside a secondary index. Nothing calls them.

**`TMcpIndexByDateTime` does not cover this.** It exercises index-by *parameters* of DATE and
TIMESTAMP in `generic_testd`. CHARGLT's shape is a TIMESTAMP column inside a *secondary index* on a
table — a different path.

**MCPDEMO is the customer-facing surface.** It is what `deploy/aws/demo.sh` deploys, what the
Marketplace listing demonstrates, and the config a first-time user meets. Today no test in this
repository touches it: the Java suite has zero references to `ROOM_MANAGER`, `getRoomList` or any
hotel object. The only behavioural coverage anywhere is `test/test_room_manager.py` **inside the
demo repo**, run by hand, with no CI in that repo at all.

## Phase 0 — four decisions (DECIDED 2026-09-09, David)

All four settled as recommended. The reasoning is kept because each has a cost that will look like a
mistake later if the reason is not to hand.

| Decision | Answer |
|---|---|
| Account | **`MCPDEMO` / `mcpdemo`** — matches the shipped config, so no credential rewriting |
| DDL home | **Copy into `app/sql/`**, and delete the stale `mcp_demo_hotel*.sql` pair |
| `PACKAGE_NAME` | **Rewrite to `mcpdemo…`** rather than `com.mcpdbwizard.customer` |
| Smoke scope | **Binds, executes, plausible shape** — behaviour stays in the demo repo's Python test |

The original statement of each, with its cost:

**1. The MCPDEMO account name.** The config says `MCPDEMO`, no underscore. FREE26 already carries a
*different* account called `MCP_DEMO`, **with** one. Creating `MCPDEMO/mcpdemo` everywhere keeps the
config unmodified, at the cost of two similarly-named demo accounts on one box — and confusing those
two has already cost an account lockout, whose logs showed only the ORA-28000 consequence and never
the ORA-01017 cause. *Recommendation: `MCPDEMO/mcpdemo`, and say at the site why the near-miss with
`MCP_DEMO` is tolerated.*

**2. Where the demo DDL lives.** Either copy it into `app/sql/` (the charglt precedent: offline,
repeatable, and `app/sql/` does not ship) or have `testdata2.sh` read the demo checkout. A copy
drifts — and `app/sql/mcp_demo_hotel.sql` + `mcp_demo_hotel_data.sql` are standing proof, being a
stale copy of this very schema that predates the demo repo's `6768d0d`. *Recommendation: copy, and
delete the stale pair in the same change, so there is one copy rather than three.*

**3. `PACKAGE_NAME`.** The demo config generates into `com.mcpdbwizard.customer`, which shadows our
own `com.mcpdbwizard.*` namespace on the test classpath. *Recommendation: rewrite it to `mcpdemo` in
the derived propfile — a deliberate divergence from the demo repo's config, documented at the site.*

**4. What "smoke" means.** That every exposed surface binds, executes and returns a plausible shape
— not that the hotel logic is right. The demo repo's `test_room_manager.py` already does the
behavioural half and should not be duplicated here.

## Phase 1 — provision MCPDEMO on all six boxes

**DONE, 2026-09-09** — all six boxes, zero invalid, counts identical. CHARGLT needed nothing here.

**Two things the run found, and the second is a defect in the demo repository.**

**The check earned its place immediately.** ORCL12's first load came out with one procedure and no
package at all — my own 300-second timeout had killed sqlplus mid-file on the slowest box in the
estate. Every object that *did* exist was correctly named, so `check_provisioning.sh` would have
passed it; `mcpdemo_check.sql` asks a different question and caught it.

**The demo DDL pinned two indexes to `TABLESPACE "USERS"`** — `ROOM_BOOKINGS_CUSTOMER` and
`ROOM_BOOKINGS_HOTEL_NAME`, an artefact of wherever that schema was first exported. An index needs
no segment until there are rows, so both CREATE cleanly and the failure lands somewhere else
entirely: **92 inserts into ROOM_BOOKINGS fail with ORA-01950** while every other table loads,
leaving a schema that looks complete by object count with its central table empty.

**FIXED UPSTREAM** in the demo repository (`6ffa568`), not worked around here. The first fix WAS a
workaround — a quota grant on USERS in `sql/mcpdemo.sql` — and it would have made the symptom go
away locally while leaving it in place for every customer who deploys that schema into a database
without a USERS tablespace or without quota on it. The grant is gone; the schema now needs exactly
one tablespace, its own.

**Verified the way a fix like this has to be** — by loading into an account with quota on its own
tablespace ONLY, so the load fails if the DDL still names USERS. All six boxes: zero invalid, 13
indexes, all 92 bookings.

1. **`app/sql/mcpdemo.sql`** — new, run as SYSTEM, taking `&1` alias and `&2` datafile directory,
   modelled line-for-line on `charglt.sql`. It must grant quota **explicitly**: from 12c `RESOURCE`
   no longer implies `UNLIMITED TABLESPACE`, and ORCL19's default permanent tablespace is SYSTEM, so
   without it every insert in the DML fails `ORA-01950`. `charglt.sql`'s header records this trap and
   the demo DDL would hit it identically.
2. **Schema and data** from the demo repo's `db/mcp_db_demo_ddl.sql` and `db/mcp_db_demo_dml.sql`,
   loaded as MCPDEMO. The DDL creates objects unqualified, so it must run *as* that user.
3. **Wire into `Scripts/testdata2.sh`** beside the CHARGLT block, same `$SQLPLUS` shape, so a bare
   `Scripts/testdata2.sh` provisions all six aliases.
4. **Assert zero INVALID objects, per alias.** Not optional. `ROOM_MANAGER` is exactly the object
   that was silently invalid below 21c, and `check_provisioning.sh` reports objects **by name** — it
   would pass a box holding a broken package, which is the identical hole that let a package with
   missing routines through after a box came back from an outage, costing `generic_test1` six files
   with nothing saying so.

**Verification.** Object counts equal across boxes and zero invalid on each. ORCL12 is the one that
decides it: the three faults fixed in the demo repo's `6768d0d` (a cursor `FOR` loop over a cursor
variable, a 31-character constraint name, `NOKEEP`/`NOSCALE`/`GLOBAL` on the sequences) were each
hidden behind the last, so one clean pass there is worth five elsewhere.

## Phase 2 — both configs in the default generation set

**DONE, 2026-09-09.** The propfile is derived, the glob is widened (35 → 37 configs), and both
floors are measured on four boxes spanning all three dictionary behaviours — ORCL12 (full
`ALL_ARGUMENTS`), XE18 and ORCL19 (truncating), FREE26 (23ai line):

| | ORCL12 | XE18 | ORCL19 | FREE26 | floor set |
|---|---|---|---|---|---|
| `mcpdemo` | 146 | 146 | 146 | 146 | **146** |
| `charglt` | 97 | 97 | 97 | 97 | **97** (unmoved) |

**No cross-version spread, and that contradicted the prediction this plan made.** The unfloored
note argued for one, because `UPSERT_CUSTOMER` takes a `CUSTOMERS%ROWTYPE` and
`ROOM_MANAGER.getRoomList` returns a strong `REF CURSOR` — the shapes 12c reports in full and later
versions truncate. Wrong, and wrong for a good reason: those are exactly what the record-field
synthesis and `adoptRefCursorRowType` were built to reconstruct. A new schema carrying both,
generating identically from 12.1 to 26ai, is evidence that work holds. A spread would have been a
gap in the synthesis, not an Oracle quirk.

**The floor was proven to bite** — set to an impossible 999, the run exits 1 with FILE-COUNT
COLLAPSE rather than passing; restored afterwards.

The tree carries what Phase 3 needs: `RoomManagerRoomcursor`/`…Attrs` and
`RoomManagerBookingcursor`/`…Attrs` (both strong ref cursors, adopted), `CustomersAttrs` (the
`%ROWTYPE` record param), `UpsertCustomer`, `HotelOccupancy`, `RoomManagerBookroom`,
`RoomManagerGetroomlist`, and the statement cursor classes.

1. **Derive `app/Propfiles/mcpdemo.pb2` with `ConfigConverter`**, never by hand — the rule the 18
   `.json` siblings already follow: byte-for-byte the converter's output, so regenerating cannot
   drift it. Apply decision 3 to `PACKAGE_NAME` afterwards, as a single visible edit.
2. **Widen the no-arg glob.** `Scripts/testrun_current.sh` (~line 291) is
   `ls "$HOMEDIR"/Propfiles/generic_test*.pb2`; it becomes that plus `charglt.pb2` and `mcpdemo.pb2`
   named explicitly. **Not a rename to `generic_test*`** — neither is a generic test, and naming
   them so would misdescribe both. `estate.sh:122` already globs every `.pb2` and needs no change.
3. **Measure and add a `mcpdemo` line to `expected-file-counts.txt`**, on the lowest-counting box,
   never by arithmetic. The blast radius of a config change is wider than its own diff: generation
   also picks up `.sql` files found in the directory that the config never names.
4. **Re-measure the CHARGLT floor** at the same time. 97 was measured before this work.

`testrun_current.sh` already rewrites `HOSTNAME`/`PORT`/`ORACLE_SID` per box and keeps `USER`/`PASS`
from the propfile, so neither config needs per-box handling beyond what exists.

**Watch for:** the no-arg propfile count moves 35 → 37, and the estate leg gets longer on every box.
Both are expected; neither is a regression.

## Phase 3 — the harnesses

**DONE, 2026-09-09.** Four harnesses, **39 checks**, green on XE18 and ORCL12:

| Harness | Checks | Covers |
|---|---|---|
| `THotelTables` | 14 | 6 table managers, FK-child / unique-index / array-index lookups, COMPLAINTS insert + delete |
| `THotelRoutines` | 6 | strong ref cursor, weak ref cursor, `%ROWTYPE` record param, BookRoom |
| `THotelStatements` | 6 | the 5 curated statements and the sequence |
| `TChargltSurfaces` | 13 | 10 procedures, 3 tables, **both TIMESTAMP index lookups** |

**Two assertions are written so the old defects would FAIL them**, which is the only reason this is
worth more than a call-and-see-if-it-throws:

- charglt's index lookups assert **the column, not the row count**. `processMany` returned rows
  with a null TIMESTAMP, so counting rows would have passed against it. The lookup is seeded with a
  value read out of the same table, so it cannot pass by legitimately finding nothing either.
- `getRoomList` reads the **typed array**. Before PR #1 it degraded silently to an untyped rowset
  while still returning rows, so a test reading `getParamPResults()` would have passed against the
  broken generator. `HOTEL_OCCUPANCY` sits beside it as the weak `SYS_REFCURSOR` that correctly has
  no typed array — the contrast is what makes the first assertion mean something.

**A green result was not taken at face value.** Three harnesses ran in under a second, so the logs
were read rather than the exit code trusted: every check reports real data
(`getRoomList OK (6 rooms, typed as RoomManagerRoomcursor)`, `COMPLAINT_ID_SEQ OK (22 -> 23)`,
`index lookup OK (1 rows, TXN_TIME populated)`). **Cleanup was verified against the box afterwards**
rather than assumed from the code: 0 bookings in 2099, 0 probe complaints, 0 probe user.

**Still to do:** the other four boxes. XE18 and ORCL12 cover the two dictionary behaviours these
schemas actually exercise, but a full six-box pass is what the estate exists for.

Four classes in `app/src/test/generated-harnesses/com/mcpdbwizard/test/`, each extending
`AbstractLiveDbHarness` and opening its **own** `SAAdminWrangler` against the schema it owns — the
pattern `TMcpIndexByRaw:70` already uses for a harness whose objects are not owned by the suite's
default account:

```java
gtWrangler = new SAAdminWrangler("", DbTestSupport.HOST, DbTestSupport.PORT,
        DbTestSupport.SID, "MCPDEMO", "mcpdemo", theLog, null);
```

| Harness | Covers |
|---|---|
| `THotelTables` | the 8 table managers — read paths for all, insert on `COMPLAINTS` (the only `CR`) |
| `THotelRoutines` | `UPSERT_CUSTOMER`, `HOTEL_OCCUPANCY`, `ROOM_MANAGER.getRoomList`, `ROOM_MANAGER.BookRoom` |
| `THotelStatements` | the 5 curated statements and `COMPLAINT_ID_SEQ.nextval` |
| `TChargltSurfaces` | the 10 procedures and 3 tables, **including all five TIMESTAMP index lookups** |

**Three shapes make these worth more than their size suggests:**

- `ROOM_MANAGER.getRoomList` returns a **strong** `REF CURSOR RETURN hotel_rooms%ROWTYPE`. That is
  the exact shape of the dictionary defect fixed in PR #1, which degraded silently on every box but
  12c — the wrapper was unaffected, so nothing announced it. Free cross-version coverage of a path
  that has already broken once.
- `HOTEL_OCCUPANCY` returns a weak `SYS_REFCURSOR`, so the two sit side by side in one harness.
- `UPSERT_CUSTOMER` takes a `CUSTOMERS%ROWTYPE` **record** parameter, which exercises the record
  crossing that known issue 3 is about.

**Mutation and cleanup.** `BookRoom` commits, and so does CHARGLT's `DelUser`; neither can lean on
rollback. Borrow the discipline the demo repo's own `test_room_manager.py` already worked out: book
into far-future 2099 ranges nothing else uses, delete exactly those rows at the end, and set a
`call_timeout` so an abandoned session holding locks fails with a clear message instead of hanging.
This estate has been bitten by zombie sessions on ORCL19, where thirteen failures read exactly like a
record regression.

**Two CHARGLT procedures need care:**

- **`SendToKafka` is a stub** — `BEGIN NULL; END`. Calling it proves it binds and nothing more. Do
  not write an assertion about Kafka; there is nothing there.
- **`GetAndLockUser` takes a soft lock** and `DelUser` commits, so both need the cleanup discipline
  above.

**Gating.** Use the marker-file profile shape `no-gen23ai` already uses, so a box without one of
these schemas drops the affected harnesses rather than failing to compile. Without it, a box
provisioned late fails in a way that reads like a generator fault.

**Final verification.** A full six-box `estate.sh` run. Budget roughly two hours, of which ORCL12 is
40-50 minutes; treat individual leg times as weather, not as a budget.

## Traps this repository has already paid for, which apply here

- **A check narrower than the thing it certifies is worse than none, because its answer gets
  believed.** `check_provisioning.sh` reporting by name is why Phase 1 asserts on invalid objects
  rather than on presence.
- **Never run the tests after a regen that failed.** A failed regen leaves a stale
  `target/regen/generated.jar`, and the harnesses compile against the **jar**, not
  `target/regen/Src`. The symptom is a compile error in an unrelated harness naming a class the
  emitter plainly writes — it reads exactly like a generator regression, and inspecting the source
  tree actively misleads. Check `unzip -l target/regen/generated.jar` and its mtime.
- **Verify a negative control actually controlled.** Both a `git stash` that stashed nothing and an
  `MCPDBWIZARD_EXTRA_CP=` that `boxes.env` then refilled have wasted time in this repository by
  producing a "without" run that silently had the thing.
